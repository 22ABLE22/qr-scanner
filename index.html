Three steps, no round trip

The browser already has everything it needs to turn pixels into text.

Step one

Drop the image

Drag a file, paste a screenshot, or pick from the camera roll on a phone. Nothing is read until you choose it.

Step two

Decode locally

Canvas pixels go to a small JavaScript decoder first. A larger WebAssembly engine loads only when the first pass misses.

Step three

Take the text

Copy it, open it, or save it as a file. Links are opened in a new tab with no referrer and no opener.

Why it stays small

Most QR sites ship a whole app. This one ships a decoder and a text box.

95 KB first load

Page, styles, font, and the JavaScript decoder together, compressed. That decoder alone is 251 KB raw and handles almost every clean QR image.

1 MB only on demand

The WebAssembly engine covers rotated, inverted, and low contrast codes. It is fetched the first time it is needed, then cached.

0 network calls

No image upload, no analytics, no fonts from a CDN. Load the page once and it keeps working offline.

Fork it and ship your own copy

No build step, no server, no dependencies to install. The folder is the site.

git clone https://github.com/22ABLE22/qr-scanner.git
cd qr-scanner
# edit, commit, push

Then in the repository open Settings, Pages, set the source to the main branch at the root. It goes live at https://<you>.github.io/qr-scanner/ with HTTPS and a service worker included.

Questions people ask before dropping a code

Does my image get uploaded anywhere?

No. The file is read with the browser File API and drawn to a canvas that stays in memory. There is no upload endpoint in the code, and the page works with the network switched off after the first load.

Can I scan with my phone camera instead?

Yes, on browsers that support it. Open the camera from the same page and hold the code in frame. Camera access is requested only after you tap the button, and frames are decoded in memory at the same place as files.

Does it work offline?

After the first visit the page and the JavaScript decoder are cached by the service worker, so it opens on a plane or in a basement. The WebAssembly engine is cached the first time it downloads.

Which image formats are supported?

Whatever your browser can draw: PNG, JPEG, WebP, GIF, AVIF, BMP, and SVG. Animated files are decoded from their first frame.

Can it read more than one code in a picture?

The fast pass returns the first code it finds. The WebAssembly pass can return several, and every result gets its own row with copy and open buttons.

What makes a code unreadable?

Glare, motion blur, or a photo taken at a steep angle. Cropping to the code and taking a second, sharper shot fixes most failures. Codes with heavy artistic overlays on the finder patterns are the hard limit.

Is there a file size limit?

Large photos are downscaled to fit a 1600 pixel canvas before decoding, which keeps memory flat. A 40 MB photo and a 4 KB screenshot behave the same.

Can I host my own copy?

Yes. The whole site is static files, so GitHub Pages, Cloudflare Pages, or a USB stick all work. Fork it, replace the sample, and push.
